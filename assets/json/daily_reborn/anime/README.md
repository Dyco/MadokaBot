# 二次元投胎数据包

核对日期：2026-10-19，资料版本 `2026.10.19.3`。支持《死神》《咒术回战》《鬼灭之刃》《火影忍者》《海贼王》《全职猎人》《钢之炼金术师 FA》《进击的巨人》八个世界。所有文件使用 UTF-8；运行时由插件的公共资源入口与 core `JsonDataStore` 读取，实际目录为 `assets_path/json/daily_reborn/anime/`。更新 JSON 后调整 `manifest.json` 的 `version`，重启机器人使缓存生效。

`/投胎二次元` 随机选择一个作品，每天免费一次；`/投胎二次元 重开` 消耗 5 积分，需先领取当天免费结果。所有作品共用本模式的次数与最近十次历史，与其他投胎模式独立。图片聚焦身份、能力、评级与历史，不展示资料范围、引用编号、来源列表、版本及资料说明；来源仍保存在 JSON 和结果快照中，文字版保留详细引用。命令遵循全局 `COMMAND_START`，这里以 `/` 为例。

## 资料与玩法的边界

- 世界、机构、种族、能力名称和正式等级来自已检索的资料，以官网为优先依据，结合百度百科与萌娘百科核对。没有通过核对的同人设定、搜索摘要推算和跨作品战力换算不进入资料池。
- 萌娘百科主站未返回完整正文；`sources.json` 明确标记实际读取的非官方镜像，并保留 `original_url`。基础体系优先与官方资料交叉核对；岩柱武器形制目前引用镜像人物条目，来源限制单独注明，不描述为已核验主站全文。
- 身份组合、性别概率、作品权重与条目权重属于游戏规则，不是原作人口统计。匿名身份使用设定原型，不代表原作新增了同样的人物，也不替换原作成员。
- 本模式展示模拟身份与成长阶段，不把队长、特级术师或柱的成熟能力描述为婴儿出生时的即时战力。
- 《死神》按组织职级与能力方向展示，灵压没有统一量表则标记未量化；《咒术回战》区分正式评级、术式与咒力，两种天与咒缚不混合；《鬼灭之刃》使用呼吸法、队阶与后勤身份，不增加其他作品的能量字段。
- 新增作品分别使用忍村与修行方向、海军军衔与果实类别、猎人资格与念修行、炼金职业与国家资格、墙内兵团与训练经历；不强行套用统一战力字段。
- 当前收录原作中的部分身份与修行方向，并非作品设定全集。各作品的 `scope` 指定采用范围；《钢之炼金术师》仅用漫画／FA 体系，《进击的巨人》仅用早期墙内兵团。
- 本版登记 52 条来源、315 个池条目，共 870 条可达配置路径。已补充学生、入队前受训者、学徒与海军低阶身份；候选不超过四项的字段和仍待处理内容见[小范围字段整理](pool-review.md)，上一版资料核对见[核验记录](validation.md)。组合数量表示配置路径，不是原作人物数量或战力统计。

## 作品格式

每个作品文件包含：

| 字段 | 含义 |
| --- | --- |
| `id`、`title`、`weight` | 稳定标识、展示标题、选择该作品的相对权重 |
| `description`、`scope` | 世界简介与资料采用的剧情阶段、身份范围 |
| `pools` | 按顺序执行的字段抽取池，可定义任意作品特有字段 |
| `sections` | 卡片和文字版的分区标题与字段顺序 |
| `history_fields` | 用于历史摘要的可见字段 ID，顺序决定拼接顺序 |

每个抽取池由 `id`、`label`、`options` 组成。除 `rating` 外的可见池必须在 `sections[].fields` 中恰好出现一次；`rating` 单独展示。所有作品保留 `faction` 与 `rating` 池以提供统一的阵营、评级快照。

可选 `hidden: true` 用于不直接展示的关联原型。例如，咒术回战先抽取隐藏的 `route`，其后多个字段同时依赖该原型，避免任意拼接导致同一身份既没有咒力、又具有广域高输出。隐藏池依然必须注明资料来源。

每个条目包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 当前池内唯一的稳定标识 |
| `value` | 展示值，使用已核对的原作术语或明确的资料空缺标记 |
| `weight` | 当前符合条件的候选集合中的相对权重，必须为有限正数 |
| `source_refs` | 非空来源 ID 列表，必须指向 `sources.json` |
| `description` | 可选的简短设定说明，与值一并保存进结果 |
| `requires` | 可选的前置条件，键只能引用此前抽过的池，值为允许的条目 ID 数组 |

`requires` 的不同键同时满足，同一键的 ID 数组满足其中一个即可。不写条件的条目会与满足条件的条目一起参与抽取，**不是默认兜底项**。条件只做 ID 比较，不支持 Python、模板表达式、脚本或网络请求。

例如，死神资料中虚圈活动地仅对虚圈破面阵营开放：

```json
{
  "id": "hueco_mundo",
  "value": "虚圈",
  "weight": 1,
  "requires": {"faction": ["hueco"]},
  "source_refs": ["bleach_official_terms"]
}
```

这段是既有 `region` 池的一个条目，需要与作品的其他字段和来源登记一起使用，不是完整的作品文件。

## 扩展步骤

1. 检索作品官网、设定集公开资料和百科，核对术语、机构、评级、能力前提及剧情阶段。把实际读到的地址与确认事实录入 `sources.json`；无法读取或存在冲突的内容写入来源限制，不直接收录。
2. 新增或修改作品 JSON。先确定身份与阵营，再定义依赖它们的地区、能力、评级；涉及先天条件、传承、特定阶段的内容用共同原型或前置条件关联。候选不超过四项时，先按原作补充可确认的入门或低阶阶段，同时检查筛选后的实际候选数；无法下扩的记录到 `pool-review.md`，不补造原作等级。
3. 在 `sections` 指定字段显示顺序，在 `history_fields` 指定足以区分结果的摘要。新增战斗体系、装备、职业、家系等字段均可通过新的池实现。
4. 新增作品时将文件名加入 `manifest.json.world_files`，修改资料版本，再重启机器人。无需新增命令、数据库表、Python 分支或 HTML 分支。

首次加载会检查标识、权重、前向引用、来源引用、展示字段以及所有可达条件分支。任何分支没有候选或条目永远不可达都会直接报告资料错误，不用随机兜底掩盖错误。

每日结果保存作品说明、抽中条目的显示值与来源、资料版本；最近十次记录保存当时的作品、性别、评级和摘要。更新 JSON 不回算已有结果或历史。若需要新的计费、抽取运算机制或持久化行为，应调整业务代码并单独审查，不能通过配置注入代码。
