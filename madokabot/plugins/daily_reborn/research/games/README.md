## 资料与玩法的边界

资料来自萌娘百科相关条目、百度百科、HoYoWiki、米游社资料、BWIKI、PRTS、灰机百科、异环信息站与Mooncell，54条来源逐项登记在 [sources.json](../../../../../assets/json/daily_reborn/games/sources.json)。每条登记保留标题、地址、发布方、类型、核对日期、实际读取方式、采用事实及限制。字段选项通过 `source_refs` 引用来源。 图片只展示身份、游戏字段、投胎评级与历史，不渲染资料范围、字段说明、来源编号、来源清单或资料版本；溯源信息保留在JSON和文字版。

原作术语与基础养成边界保留资料来源。按用户确认的玩法规则，各游戏投胎评级至少五档，只向下补充，不提高原有最高档：原神、鸣潮、星铁与FGO为1至5星，绝区零与异环为D/C/B/A/S，明日方舟为2至6星。原作未提供的低档及低星身份组合明确记为 `basis: "gameplay"`，不伪造百科出处；有来源的档位默认 `basis: "original"`。低档沿用本游戏已有成长模板，不凭空编造另一套数值上限。

随机性别、字段组合、具体数值及等权重概率为本插件玩法，并不对应既有人物或原游戏卡池。七款游戏各档位权重均为1，每个前置身份分支均可抽到五档评级。这里展示的是随机成长档案，不是婴儿即时面板。没有公开统一量纲的“美貌、天赋潜力、综合战力”不编分，也不将投胎星级包装成官方战力评分。

## JSON 接口

运行数据位于 `assets/json/daily_reborn/games/`；资源根目录遵循项目 `assets_path` 设置。没有在线生成、运行时爬取或自动接受未核实网页的步骤。

- `manifest.json`：`schema_version`、`version`、`title`、`notice`、`genders`、`world_files`。游戏等权抽取，性别等权抽取，权重均是玩法规则。
- `sources.json`：来源登记数组。新增来源标识须唯一；保留原始链接、读取方式、采用事实和局限。
- 每款游戏JSON：`id`、`title`、`weight`、`description`、`scope`、`sections`、`history_fields`、`pools`。文件名加入 `world_files` 即可参与抽取。
- 异环的可选 `lore` 为世界观研究归档，保存机构职能、总部关系、部门编制、暂未参与抽取的组织/地区及用户提供的待核实线索。抽取器只使用 `pools`；归档不自动变成可抽取事实。`headquarters_city: null` 表示未核实，不能据此补造城市对应关系。核实后维护 `pools`、`sections` 与来源即可扩充玩法。
- `sections` 决定分区标题、字段及顺序；各游戏可完全不同。`history_fields` 指定历史摘要，不要塞入过多长文本。
- `pools` 按顺序抽取。每个池有 `id`、`label`、`options`，可用 `hidden: true` 保存内部联动字段。保留 `faction`（身份/归属/力量来源）和 `rating`（各游戏投胎评级）；`rating` 单独展示，无需加入 `sections`。
- 离散选项含 `id`、`value`、`weight`、`source_refs`，可附 `description`。默认 `basis: "original"` 的选项必须有可核实来源。自定义选项使用 `basis: "gameplay"` 并填写中文 `description`，说明扩展规则；`source_refs` 可以为空，不得为自定义设定伪造网页引用。混合原作模板与自定义组合时可保留模板来源，同时在说明中区分二者。完整结果快照保存 `basis`；图片只显示“投胎评级/投胎星级”和档位，不额外渲染依据标签。
- 数值选项用 `range: [最小整数, 最大整数]` 与 `unit` 代替 `value`，在闭区间内等概率抽取。原作数值上下限必须有来源；自定义下扩必须标明玩法依据，不填任意0至100“战力”。需要不同精度时先明确原作单位再扩展代码。
- 条件选项用 `requires: {前置池id: [允许的选项id]}`。不同字段之间为“且”，同字段的列表为“或”，只允许引用前面的字段。不支持表达式、脚本、动态导入或字符串代码执行。

例如以下当前等级选项只在抽到 `stage` 池中的 `s6` 后可选；对应游戏中该阶段允许80至90级：

```json
{
  "id": "lv6",
  "range": [80, 90],
  "unit": "级",
  "weight": 1,
  "requires": {"stage": ["s6"]},
  "source_refs": ["genshin_growth"]
}
```

原神、鸣潮、星铁、绝区零与异环的等级不低于已完成的突破门槛。FGO再临不重置等级，等级范围同时引用星级与再临阶段；全部职阶允许1至5星，原作未实装的低星组合使用玩法标记；原作各星级再临成长范围继续保留。异环的共鸣门槛只引用已激活觉醒数量，不按编号分配个人效果。明日方舟精英化后等级重置为1，按星级与精英阶段选取上限；2星仅精英0且等级上限30、无主动技能；3星精英0/1上限40/55且不能精英2。3至6星基础技能在精英0上限4、精英1/2上限7，本版不分配技能专精。上述规则均写在JSON中，抽取器不按游戏名硬编码。

加载时检查唯一标识、有限正权重、资料引用或自定义玩法说明、展示字段、前向依赖、全部可达分支及整数范围。JSON更新后重启生效；旧档案按已保存的字段、数值、来源与资料版本展示，不用新配置重新计算。当前模式键为 `games`，新表为 `madoka_daily_reborn_games_record`，不改动其他模式的数据表或持久化键。

## 后续更新

1. 先检索萌娘百科和百度百科，再找官方资料与游戏专门Wiki交叉核对；记录实际读取方式，无法证实时暂不收录。
2. 变动只涉及分类、地区、范围、条件或新游戏时，更新运行JSON及来源登记，递增 `version`，同步 `scope` 和本文范围。
3. 新增字段时在 `pools`、`sections`（或隐藏标记）和需要的 `history_fields` 中登记，保证所有依赖分支有可用选项。
4. 每款游戏的评级至少五档，只允许在最高档以下补充；自定义档位与组合标记 `gameplay`，不能借原作引用冒充官方设定。数值下扩必须同步检查相关阶段、技能与身份条件。
5. 只做代码与JSON的静态检查，不新增或执行测试。不要更改已保存的历史结果，不把尚未核实的传闻合并进可抽取池。
